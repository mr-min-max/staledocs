# StaleDocs walkthrough recording checklist

Use this checklist for the optional 60 to 90 second full walkthrough. The
checked-in GIF is the deterministic README animation. It is not a substitute
for a reviewed live recording.

## Recording setup

- [ ] Start from a fresh disposable repository with only public, synthetic
      example content.
- [ ] Follow only the public instructions and the reviewed walkthrough script.
- [ ] Capture at 1080p or higher.
- [ ] Keep all visible text readable at a 24px-equivalent size.
- [ ] Include English captions even if there is no narration.
- [ ] Keep the five narrative blocks in the order and timings in the VTT.

## Privacy and truth

- [ ] No visible accounts, API keys, tokens, or credential assignments.
- [ ] No local absolute paths, personal notifications, terminal history, or
      unrelated application windows.
- [ ] Do not show a raw preparation digest, private prompt, or private source.
- [ ] State that the checked-in animation is deterministic and does not claim
      to invoke Codex; show the live Codex host workflow only in the recording.
- [ ] Keep the example's `README.md` and `API.md`,
      `prepare_documentation_update`, and `validate_documentation_draft`
      truthful and in their reviewed order.
- [ ] If ElevenLabs narration is used, disclose in the video description that
      ElevenLabs narration is synthetic.

## Export and review

- [ ] Run a final privacy scan on the screen recording, captions, thumbnail,
      description, and upload notes.
- [ ] Check the focused diff and the `Review the diff` handoff before any
      repository write.
- [ ] Confirm the reviewed upload is visible from the public viewer path before
      sharing it.
- [ ] Confirm the `Public beta` invitation does not make adoption, endorsement,
      or provider-generation claims.
- [ ] MP4 is not committed to Git and is optional for Gate A1 and Gate A2.
