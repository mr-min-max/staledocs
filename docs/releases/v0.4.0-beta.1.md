# StaleDocs 0.4.0-beta.1

Status: Published prerelease

## What changed for users

- TypeScript and JavaScript public APIs are resolved from package entries and bounded static re-exports, with explicit fallback when no supported entry is available.
- Entry-only changes can expose or hide existing symbols. Python boundaries use package roots, literal `__all__`, relative imports, and private underscore paths.
- Review reports fold duplicate member rows, avoid false unmentioned-class rows, and do not treat changelog history as stale prose.
- Non-enumerable CommonJS and unsupported files are reported as not analyzed rather than silently presented as clean.
- `comment: on-findings` keeps Action comments to stale or breaking verdicts.
- Markdown discovery covers root documents, common documentation directories, package-local Markdown, configured output, and safe `docs` paths with bounded deterministic scans.
- `entry` and `docs` configuration can specify repository-relative paths. Recommendations prefer the nearest README.

The plan, context, and review schemas keep their existing v1 identities. Boundary reports, visibility, internal-change counts, not-analyzed details, and documentation-limit reporting are optional additive fields.

## Evaluation proof

Ten targets were labeled and approved before either package ran: seven TypeScript targets and three Python targets, including two INTERNAL cases, two NO-PUBLIC-CHANGE controls, and one DOCS-STALE case. Quota-driven skips and a documentation-only control were approved by the owner before execution; reasons remain recorded privately.

The published `staledocs@0.3.0-beta.1` matched 4 of 10 expectations. The published `staledocs@0.4.0-beta.1` matched 6 of 10 and did not regress on any label class. The generated before/after table is in [`docs/EVALUATIONS.md`](../EVALUATIONS.md).
