# StaleDocs 0.5.0-beta.1

Status: Release candidate, not published

## What changed for users

- Validation by target: `validate_documentation_draft` checks a draft against the server's latest preparation for its `target`, so an assistant no longer relays the signed digest between calls (#49). A supplied `preparation_digest` must still be exact, and stale or changed targets still fail closed.
- Structured MCP results: every MCP tool declares an output schema and returns its JSON result as `structuredContent` as well as text.
- Review tool: the read-only `review_documentation_impact` MCP tool returns the `aidoc.review.v1` report that `staledocs review --format json` prints.
- Audit: `staledocs audit` and the `audit_documentation` MCP tool make one pass over the working tree's Markdown, including `AGENTS.md`, `CLAUDE.md`, and the Copilot instructions file, and report package scripts, repository paths and links, and public TypeScript class members that no longer exist.
- Stale means a contract change: a document is stale only when a public symbol it mentions changes its signature, kind, or public visibility. Edits inside a body or a doc comment keep the review clean and `check` at exit 0.
- Python constructors: a change to the `__init__` signature of a public class is a `contract-changed` class with the facet `constructor`, and the class carries the constructor's arity. Edits inside `__init__` stay implementation changes.
- Codex plugin: `codex plugin marketplace add mr-min-max/staledocs` and `codex plugin add staledocs@staledocs` install the `check`, `review`, and `maintain-documentation` skills and a StaleDocs MCP server pinned to this release.
- Claude Code plugin: the repository marketplace installs the same three skills with the same pinned server.
- `AGENTS.md` describes the repository for coding agents: layout, commands, rules, and the definition of done.
- MCP Registry: `server.json` describes the npm package as the local stdio server `io.github.mr-min-max/staledocs`, and the release workflow registers it after npm accepts the package.
- Anthropic provider for the legacy generators: the default model is `claude-sonnet-5-5` on `@anthropic-ai/sdk` 1.x (API version `2026-10-21`); requests no longer send `temperature`, the default `max_tokens` is 16000, and a response cut at `max_tokens` or refused fails instead of returning partial text.
- Dependencies: dotenv 18.0.9, the OpenAI SDK 7.43.0, ESLint 10.13.0, and typescript-eslint 8.72.0, together with the SDK, `glob` 13, `diff` 9, and `simple-git` 4 updates listed in the [changelog](../../CHANGELOG.md).

The plan, context, review, preparation, and validation schemas keep their v1 identities; `aidoc.audit.v1` is new. New fields and the `constructor` facet are optional and additive.

## Evaluation proof

The published package runs against the ten approved corpus targets only after publication. That comparison is recorded here and in [`docs/EVALUATIONS.md`](../EVALUATIONS.md) by the follow-up change. No result for the unpublished candidate is claimed here.

## Remaining owner gates

- Merge this change after review, then repeat the release checks at the clean `main` commit.
- Push the annotated `v0.5.0-beta.1` tag and confirm the `verify`, `publish`, `github-release`, and `mcp-registry` jobs.
- Move npm `latest` and `beta` and the GitHub Action `v0` tag, and confirm the MCP Registry entry.
- Run the Codex fix-path check once against the published package, then start the follow-up change.

Until npm publishes `0.5.0-beta.1`, the plugins' pinned launcher names a version that cannot be downloaded yet. See [RELEASING.md](../RELEASING.md) for the procedure.
